2. Definicje

  • Klient — osoba fizyczna korzystająca z bota Telegram salonu w celu rezerwacji wizyt.
  • Specjalista (Mistrz) — osoba fizyczna świadcząca usługi kosmetyczne w salonie, korzystająca z bota specjalisty Telegram i/lub panelu administracyjnego.
  • Właściciel salonu — osoba fizyczna lub prawna zarządzająca salonem piękności, korzystająca z panelu administracyjnego SalonBot.
  • Użytkownik — ogólne określenie dla Klienta, Specjalisty lub Właściciela salonu.
  • Platforma — ogół usług SalonBot: boty Telegram (kliencki i specjalisty), panel administracyjny, API.
  • RODO — Rozporządzenie Parlamentu Europejskiego i Rady (UE) 2016/679 z dnia 27 kwietnia 2016 r.

8. Bezpieczeństwo danych

  • Szyfrowanie w transmisji: HTTPS/TLS (certyfikaty SSL automatycznie zarządzane przez Railway).
  • Szyfrowanie w spoczynku: tokeny botów i OAuth zaszyfrowane algorytmem Fernet (AES-128-CBC + HMAC-SHA256).
  • Haszowanie haseł: bcrypt.
  • Izolacja danych (multi-tenancy): filtr salon_id na poziomie zapytań do bazy danych.
  • Minimalizacja danych: zbieramy wyłącznie dane niezbędne do świadczenia usługi.
  • Kontrola dostępu: JWT z ograniczonym czasem ważności.
  • Logi diagnostyczne: adres IP, user agent, identyfikator użytkownika, data/czas, identyfikator salonu, komunikaty o błędach. Podstawa: art. 6 ust. 1 lit. f RODO.

12. Korzystanie z usług Google API

Niniejsza sekcja spełnia wymagania Google API Services User Data Policy.

12.1. Jakie dane uzyskujemy z Google API

  • Freebusy: okresy „zajętości" z kalendarza specjalisty — bez szczegółów wydarzenia.
  • Zdarzenia utworzone przez SalonBot: SalonBot tworzy, aktualizuje i usuwa zdarzenia w kalendarzu osobistym specjalisty. Odczytuje wyłącznie zdarzenia, które sam utworzył.

12.2. Jak wykorzystujemy dane Google API

  • Freebusy: sprawdzenie dostępności specjalisty — zapobiega podwójnym rezerwacjom.
  • Zdarzenia: synchronizacja rezerwacji z kalendarzem — tworzenie, aktualizacja, usuwanie.

12.3. Jak przechowujemy dane Google API

  • Refresh token: w PostgreSQL, zaszyfrowany Fernet (AES-128-CBC + HMAC-SHA256). Klucz — zmienna środowiskowa serwera.
  • Freebusy: cache Redis 10 minut, potem automatycznie usuwane.
  • Zdarzenia: w bazie przechowywany tylko event_id. Treść generowana z danych rezerwacji.

12.4. Udostępnianie danych Google API

Dane z Google API nie są udostępniane stronom trzecim. Nie wykorzystujemy ich do reklamy, marketingu, profilowania ani łączenia z innymi danymi.

12.5. Sztuczna inteligencja i uczenie maszynowe

Dane z Google API nie są wykorzystywane do opracowywania, doskonalenia ani trenowania modeli AI/ML.

12.6. Odwołanie dostępu

Specjalista może odwołać dostęp w dowolnym momencie: w panelu SalonBot lub na myaccount.google.com/permissions. Refresh token jest natychmiast usuwany.

14. Osoby niepełnoletnie

Poniżej 16 roku życia — wymagane zaangażowanie rodzica/opiekuna (art. 8 RODO). W praktyce: rezerwacja przez rodzica lub kontakt telefoniczny z salonem.

15. Naruszenie ochrony danych (data breach)

15.1. Usługodawca powiadomi salon (administratora) w ciągu 72 godzin od potwierdzenia naruszenia i podejmie natychmiastowe działania naprawcze.

15.2. W przypadku naruszenia danych specjalistów/właścicieli — Usługodawca zgłosi bezpośrednio do UODO.

16. Zautomatyzowane podejmowanie decyzji

Dane nie podlegają zautomatyzowanemu podejmowaniu decyzji ani profilowaniu (art. 22 RODO).

16a. Sztuczna inteligencja

Obecnie SalonBot nie wykorzystuje danych osobowych do trenowania modeli AI. W przypadku wdrożenia AI — Polityka zostanie zaktualizowana.

17. Zmiany Polityki Prywatności
